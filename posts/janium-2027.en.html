Janium 2027, the new version of the library and archives system, is now available. Institutions on maintenance update to this version. It is the ILS the institution already runs, with a search engine that can rank by relevance, a more readable OPAC record, inventory that continues if the browser is closed, circulation notices written by the institution, an email sign-in code and password expiry. The detail of each capability will have its own article; this text is the map.

Search engine

Keyword search can rank by relevance: the most pertinent first, not necessarily the last cataloged. It recognizes plurals and derived forms — Spanish, English and Portuguese ship with it, and other languages can be added when the catalog needs them — and does not distinguish accents when matching. If there are no exact hits, it can suggest the closest term —a typo or imperfect OCR. In the summary a snippet appears with the words marked, and while typing, suggestions from the holdings themselves.

Someone searching residencia and someone searching residencias should not get two different sets of results. Someone typing espanola without an accent should still find the heading with one. Sort by relevance changes which record comes first; it is worth testing against the institution’s own holdings before leaving it as the default. If it does not fit, catalog order can be restored or field weights adjusted. The detail is in How to search the catalog by relevance, plurals and typos.

The inverted index remains the default and the fallback. If the new engine is not turned on, keyword search behaves as it does today. Alphabetical browsing, authority control, ISBN, ISSN and classification do not go through that engine.

Whoever uses Collect to catalog with AI still delivers records to Janium. 2027 changes how Janium searches them, not how Collect produces them. The relationship between access points, full text and an optional RAG layer is in Access points, full text and RAG.

OPAC record display

In the OPAC and in the cataloging detail view, short fields (title, author, year) stay in a list. Narrative ones (summary, notes, archival description) display as a paragraph, label above, as in a printed document.

If the record has many long notes —a file, a fonds— the whole record switches to that layout. A book with a short summary stays in the mixed layout. When the summary is long, the result list offers see more or see less.

An ISAD-G record with scope notes is not read the same way as a three-field record. 2027 does not change the standard; it changes how it is presented.

Covers and other catalogs

With the ISBN, Janium can look up the book’s cover in Open Library and Google Books and attach it to the record. It does not replace a cover already in the system: it only fills those that are missing. Without an ISBN there is no automatic lookup.

In “other catalogs”, Z39.50 and SRU queries can go to several servers at once. Results show the source; one can filter to a single catalog or ask for more from one. If a server does not respond, it is flagged and the others continue. Catalogs consulted by web address, one by one, do not enter that simultaneous search.

Circulation

Batch inventory is no longer cancelled when the browser is closed or the connection is lost. Whoever starts the batch can leave and come back: the work continues on the server and the page shows which phase it is in (duplicates, not found, other library, inventoried). A second inventory cannot be started until the one in progress is closed.

Circulation notices —loan about to fall due, hold ready for pickup, hold that could not be completed because the item was lent to someone else— no longer have a fixed email body. The institution writes the greeting, the table and the closing.

The certificate of no outstanding fines can come out as Word, in addition to HTML. One template is enough for the whole system; each library can have its own.

Sign-in

There are two optional access reinforcements.

After username and password, Janium can send a six-digit code to the registered email, valid for ten minutes. No extra application is needed. If the person has no email on the profile, or the message cannot be sent, sign-in is not blocked.

If the password period the institution sets has lapsed, sign-in asks for a new password before opening the session. It also applies to the OPAC (account information and holds). Length and complexity are set by whoever administers the system.

What does not change

2027 does not replace the catalog or force a change of description standard. MARC21, Dublin Core, ISAD-G and the other formats already in use remain. Collect is not part of this version: it is another product, the one that produces records with AI; Janium is the one that searches, circulates and displays them.

After the update, the search engine, covers, email sign-in code and password expiry are turned on per institution. If they are left off, keyword search, covers and sign-in behave as they do today. The OPAC record display and background inventory are part of the version.

Limits

An automatic cover needs an ISBN and that one of the public sources has it; if not, the record is retried later, without replacing an image that already exists. A Z39.50 catalog that does not respond does not stop the others, but copy cataloging depends on the remote server answering. Sort by relevance changes which record comes first: it is worth validating with catalogers before leaving it as the default.

Without email on the profile, the email sign-in code is not completed and sign-in continues. Whoever needs to block access when mail fails will not find that behaviour in this version.
